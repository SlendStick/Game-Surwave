## Исправленная логика появления перков в селекторе

## 📋 ОСНОВНЫЕ ПРАВИЛА ЗАВИСИМОСТЕЙ

### Структура деревьев перков
```
Каждое дерево перков имеет структуру:
├── T1 (базовый перк) — всегда доступен при первом уровне
├── T2a (улучшение A) — требует T1 этого дерева
├── T2b (улучшение B) — требует T1 этого дерева
└── T3 (финальное улучшение) — требует T2a ИЛИ T2b (то, что было взято)

Пример дерева "Быстрые Стрелы":
├── T1: Скорость пуль +30%
├── T2a: Пробитие +1 (требует T1)
├── T2b: Скорость +15% + урон +15% (требует T1)
└── T3a: Снайпер +25% скорости +15% урона (требует T2a)
└── T3b: Убийца (требует T2b)
```

### Базовые правила появления перков
```
Правило 1: Базовый перк (T1)
├── Появляется в селекторе ВСЕГДА
├── Доступен с 1-го уровня
├── Не требует предварительных условий
└── Можно взять любой T1 из любого дерева

Правило 2: Улучшения (T2a, T2b)
├── Появляются ТОЛЬКО если взят T1 этого дерева
├── Нельзя взять T2 без T1
├── T2a и T2b взаимно исключающие (можно взять только один)
└── Появляются в селекторе после взятия T1

Правило 3: Финальные улучшения (T3)
├── Появляются ТОЛЬКО если взят соответствующий T2
├── T3a требует T2a
├── T3b требует T2b
├── Нельзя взять T3 без T2
└── Появляются в селекторе после взятия соответствующего T2

Правило 4: Междревесные зависимости
├── Некоторые перки требуют перки из ДРУГИХ деревьев
├── Эти зависимости ДОЛЖНЫ быть явно указаны
├── Перк НЕ появится, пока не выполнены ВСЕ зависимости
└── Система проверяет зависимости перед добавлением в селектор
```

## 🛠️ ИСПРАВЛЕНИЯ ПРОБЛЕМНЫХ ПЕРКОВ

### Проблема 1: Дерево "Святое Копьё" (#24)

**Исходная проблема:**
```
Пользователь может взять "Рыцарь Копья" (T2a) сразу после "Святое Копьё" (T1),
не имея перков из дерева "Душа" (#16), хотя "Рыцарь Копья" даёт +15 урона
за каждую собранную душу, а души требуют перков из дерева "Душа".
```

**Исправление:**
```
Дерево "Святое Копьё" (#24):
├── T1: Святое Копьё (призыв, преследует)
│   └── Появление: всегда доступно
│
├── T2a: Рыцарь Копья (+15 урона за каждую душу)
│   ├── Требование 1: T1 "Святое Копьё" (это дерево)
│   ├── Требование 2: T1 "Душа" (дерево #16) — ИМЕЕТ СМЫСЛ!
│   └── Появление: только если выполнены ОБА требования
│
├── T2b: Мастер Копья (+40% урона)
│   ├── Требование: T1 "Святое Копьё" (это дерево)
│   └── Появление: после взятия T1
│
└── T3: Святые Копья (+3 копья)
    ├── Требование: T2a ИЛИ T2b (то, что было взято)
    └── Появление: после взятия соответствующего T2
```

**Логика проверки (GDScript):**
```gdscript
func can_show_perk(perk_id: String) -> bool:
    match perk_id:
        "spear_knight":  # Рыцарь Копья (T2a дерева #24)
            return has_perk("holy_spear") and has_perk("soul_base")
            # holy_spear = T1 дерева #24
            # soul_base = T1 дерева #16
        
        "spear_master":  # Мастер Копья (T2b дерева #24)
            return has_perk("holy_spear")
        
        "holy_spears":  # Святые Копья (T3 дерева #24)
            return has_perk("spear_knight") or has_perk("spear_master")
```

### Проблема 2: Дерево "Душа" (#16) и синергии

**Исходная проблема:**
```
Перк "душа-рыцарь" (T3 дерева #16) даёт +15 урона призывов за каждую душу,
но не требует наличия призывов. Логичнее требовать наличие хотя бы одного
призыва или перка из дерева "Призыв" (#21).
```

**Исправление:**
```
Дерево "Душа" (#16):
├── T1: Душа (дропается с редких врагов, +1 HP перманентно)
│   └── Появление: всегда доступно
│
├── T2a: Сбор душ (+25% шанс дропа)
│   ├── Требование: T1 "Душа" (это дерево)
│   └── Появление: после взятия T1
│
├── T2b: Конвертация душ (через 60 сек душа → макс. HP)
│   ├── Требование: T1 "Душа" (это дерево)
│   └── Появление: после взятия T1
│
└── T3: Душа-рыцарь (+15 урона призывов за каждую собранную душу)
    ├── Требование 1: T2a ИЛИ T2b (это дерево)
    ├── Требование 2: Любой перк из дерева "Призыв" (#21)
    │   └── Логика: смысл есть только если есть призывы
    └── Появление: только если выполнены ОБА требования
```

### Проблема 3: Дерево "Призыв" (#21) и синергии

**Исходная проблема:**
```
Перк "Приз Возмездия" (T2b) синергирует с "Власть Серпа" из дерева #23,
но синергия "Власть Призыва" требует оба перка. Система не проверяет
наличие обоих перков перед показом синергии.
```

**Исправление:**
```
Синергия "Власть Призыва":
├── Требование 1: "Приз Возмездия" (T2b дерева #21)
├── Требование 2: "Власть Серпа" (T2a дерева #23)
├── Появление: только если ОБА перка взяты
└── Визуал: красная рамка вокруг иконки синергии

Проверка в селекторе:
├── Система проверяет все синергии при каждом обновлении селектора
├── Если условия синергии выполнены → синергия добавляется в пул
├── Если условия не выполнены → синергия НЕ добавляется
└── Синергия имеет приоритет над обычными перками (30% шанс появления)
```

## 💻 РЕАЛИЗАЦИЯ В GODOT (GDScript)

### Система проверки зависимостей
```gdscript
# perk_dependencies.gd
extends Node

class_name PerkDependencySystem

# Словарь всех перков с их зависимостями
var perk_requirements = {
    # Дерево 1: Быстрые Стрелы
    "fast_arrows_t1": [],
    "fast_arrows_t2a": ["fast_arrows_t1"],
    "fast_arrows_t2b": ["fast_arrows_t1"],
    "fast_arrows_t3a": ["fast_arrows_t2a"],
    "fast_arrows_t3b": ["fast_arrows_t2b"],
    
    # Дерево 16: Душа (ИСПРАВЛЕНО)
    "soul_t1": [],
    "soul_t2a": ["soul_t1"],
    "soul_t2b": ["soul_t1"],
    "soul_t3": ["soul_t2a", "soul_t2b", "summon_any"],  # Требует призыв!
    
    # Дерево 24: Святое Копьё (ИСПРАВЛЕНО)
    "holy_spear_t1": [],
    "holy_spear_t2a": ["holy_spear_t1", "soul_t1"],  # Требует душу!
    "holy_spear_t2b": ["holy_spear_t1"],
    "holy_spear_t3": ["holy_spear_t2a", "holy_spear_t2b"],
}

# Специальные требования (междревесные)
var special_requirements = {
    "soul_t3": "has_any_summon_perk",  # Любой перк из дерева Призыв
    "holy_spear_t2a": "has_soul_perk",  # T1 из дерева Душа
}

var player_perks = []  # Список взятых игроком перков

func can_show_perk(perk_id: String) -> bool:
    """Проверяет, можно ли показать перк в селекторе"""
    
    # Базовые требования (из словаря)
    if perk_id in perk_requirements:
        var required = perk_requirements[perk_id]
        for req in required:
            if req == "soul_t2a" or req == "soul_t2b":
                # Для T3 дерева Душа — нужен хотя бы один из T2
                if not (has_perk("soul_t2a") or has_perk("soul_t2b")):
                    return false
            elif req == "holy_spear_t2a" or req == "holy_spear_t2b":
                # Для T3 дерева Святое Копьё — нужен хотя бы один из T2
                if not (has_perk("holy_spear_t2a") or has_perk("holy_spear_t2b")):
                    return false
            elif not has_perk(req):
                return false
    
    # Специальные требования (междревесные)
    if perk_id in special_requirements:
        var special = special_requirements[perk_id]
        match special:
            "has_any_summon_perk":
                if not has_any_summon_perk():
                    return false
            "has_soul_perk":
                if not has_perk("soul_t1"):
                    return false
    
    return true

func has_perk(perk_id: String) -> bool:
    """Проверяет, есть ли у игрока этот перк"""
    return perk_id in player_perks

func has_any_summon_perk() -> bool:
    """Проверяет, есть ли у игрока любой перк из дерева Призыв (#21)"""
    var summon_perks = [
        "summon_t1",
        "summon_t2a",
        "summon_t2b",
        "summon_t3"
    ]
    for perk in summon_perks:
        if has_perk(perk):
            return true
    return false

func add_perk(perk_id: String):
    """Добавляет перк в список взятых"""
    if not perk_id in player_perks:
        player_perks.append(perk_id)

func get_available_perks(all_perks: Array) -> Array:
    """Возвращает список перков, доступных для выбора"""
    var available = []
    for perk in all_perks:
        if can_show_perk(perk.id):
            available.append(perk)
    return available
```

### Интеграция с селектором перков
```gdscript
# perk_selector.gd
extends Control

var dependency_system = PerkDependencySystem.new()
var all_perks = []  # Все перки из базы данных

func _ready():
    # Загружаем все перки из базы данных
    all_perks = load_all_perks()
    refresh_perk_selection()

func refresh_perk_selection():
    """Обновляет список доступных перков"""
    var available_perks = dependency_system.get_available_perks(all_perks)
    
    # Проверяем синергии
    var available_synergies = check_synergies()
    
    # Формируем финальный список (5 перков)
    var selection_pool = []
    
    # Добавляем синергии (если есть, 30% шанс)
    if available_synergies.size() > 0 and randf() < 0.3:
        selection_pool.append(available_synergies[randi() % available_synergies.size()])
    
    # Добавляем обычные перки
    while selection_pool.size() < 5 and available_perks.size() > 0:
        var random_perk = available_perks[randi() % available_perks.size()]
        selection_pool.append(random_perk)
        available_perks.erase(random_perk)
    
    # Показываем игроку
    display_perks(selection_pool)

func check_synergies() -> Array:
    """Проверяет доступные синергии"""
    var available = []
    
    # Синергия "Власть Призыва"
    if dependency_system.has_perk("summon_t2b") and dependency_system.has_perk("phantom_scythe_t2a"):
        available.append({

            "description": "+35% урона и скорости призывов, -35% урона пуль",
            "is_synergy": true
        })
    
    # Синергия "Меч и Щит"
    if dependency_system.has_perk("shield_t1") and dependency_system.has_perk("light_magic_t2b"):
        available.append({
            "id": "synergy_sword_shield",
            "name": "Меч и Щит",
            "description": "Убийства карой снижают восстановление щита на 1 сек",
            "is_synergy": true
        })
    
    # Синергия "Исполин"
    if dependency_system.has_perk("health_t2b") and dependency_system.has_perk("light_magic_t3"):
        available.append({
            "id": "synergy_giant",
            "name": "Исполин",
            "description": "+2 HP, +25% скорости, +25% размера",
            "is_synergy": true
        })
    
    return available

func on_perk_selected(perk):

    dependency_system.add_perk(perk.id)
    refresh_perk_selection()
```
