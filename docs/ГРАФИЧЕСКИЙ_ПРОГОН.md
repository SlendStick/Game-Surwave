# Графический запуск и проверка игры (снимки экрана)

Нужен, чтобы смотреть на реальный рендер: интерфейс, HUD, арт, эффекты — а не только
на текстовые проверки в headless-режиме.

Есть два пути, оба используют одни и те же хуки в коде:

| переменная | смысл |
|---|---|
| `SURW_SHOTS` | список секунд через запятую — когда делать кадры (`"10,22"`); после последнего игра закрывается |
| `SURW_SHOT_DIR` | папка для PNG (по умолчанию `user://shots`) |
| `SURW_SHOT_TAG` | префикс имени файла (`game_00_010s.png`) |
| `SURW_SHOT_KEEP=1` | не закрывать игру после кадров |
| `SURW_SHOT` + `SURW_SHOT_DELAY` | одиночный кадр через N секунд (старый вариант) |
| `SURW_PHOTO_TEST=png` | «фотография» 1280×720 посреди боя |

Плюс обычные хуки автозапуска: `--autoplay`, `--god`, `SURW_MAP`, `SURW_CHAR`,
`SURW_WEAPON`, `SURW_MODE`, `SURW_DARK`, `SURW_BOSS_TEST`, `SURW_SCREEN=select`.

## 1. На своём компьютере

Нужен Godot **4.7.2-stable** (обычная сборка, не headless).

```bash
# просто поиграть
godot --path .

# серия кадров автоматического боя на карте forest → docs/playtest/
./tools/playtest_shots.sh

# другая карта / другие моменты / свой бинарник
SURW_MAP=tundra SURW_SHOTS="6,14,30" GODOT=~/Godot_v4.7.2-stable_x86_64 ./tools/playtest_shots.sh
```

Скрипт сам подставит `xvfb-run`, если дисплея нет, но в системе он установлен.

## 2. Без своего компьютера — GitHub Actions

В `.github/workflows/ci.yml` есть джоба **«Playtest screenshots (Xvfb + OpenGL)»**:
на `ubuntu-latest` ставится Godot 4.7.2 (с кэшем) и программный OpenGL + Xvfb,
игра запускается автоматически и делает три набора кадров:

1. `game_*` — обычный бой (`--autoplay --god`, карта forest, 10 и 22 с);
2. `boss_*` — бой с боссом и смена фаз (`SURW_BOSS_TEST=0.45`, карта sands);
3. `select_*` — экран выбора героя (`SURW_SCREEN=select`).

Запуск:

* вручную: вкладка **Actions** → workflow **CI** → **Run workflow**;
* автоматически: если в сообщении коммита есть `[shots]`
  (например `git commit -m "Обновил HUD [shots]"`).

Результат:

* кадры коммитятся в ветку в папку **`docs/playtest/`** — их видно прямо на GitHub;
* те же файлы лежат в артефакте **`surwave-screens`** (скачать zip из окна запуска);
* в логе шага `Render playtest frames` печатается
  `[SURWAVE] shot=<путь> err=0 size=1280x720 scene=<сцена>`.

Если кадров нет — смотрите лог этого шага: чаще всего это отсутствие
`libgl1-mesa-dri` (тогда Godot падает на создании OpenGL-контекста) или
неимпортированные ресурсы (шаг `Import project resources`).

Запуск CI `44341041864` (коммит с `[shots]`) прошёл целиком, кадры лежат в
`docs/playtest/` и приложены артефактом `surwave-screens`:

| файл | что видно |
|---|---|
| `game_00_010s.png`, `game_01_022s.png` | бой на forest: герой, слаймы/летучие мыши, дерево, гриб, HUD (сердца, иконка навыка у шкал, таймер, XP) |
| `boss_00_008s.png`, `boss_01_014s.png` | Шемхаз: полоса «ФИНАЛЬНЫЙ БОСС: Шемхаз · ФАЗА 2/5», бумеранг, волны-зоны |
| `select_00_003s.png` | экран «ПОДГОТОВКА К ЗАБЕГУ»: вкладки, список героев, портрет Алдара, «НАЧАТЬ» |

Кадры 640×360 — это внутреннее разрешение рендера (окно 1280×720 с stretch),
тёмный фон на кадрах боя — это «Тьма» первого уровня; для светлых кадров
добавьте `SURW_DARK=0` в команду запуска.

## Чем это не является

Это не «скриншот-тест» с эталонами: кадры не сравниваются автоматически,
их смотрит человек. Статические проверки (`python3 tools/ci_validate_repo.py`)
по-прежнему не видят ошибок рендера — только структуру репозитория и код.
